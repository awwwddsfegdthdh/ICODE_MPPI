# ICODE_MPPI 项目汇报（算法改进路线）

## 1. 项目目标
- 在 MuJoCo 的 E1 机器人模型上完成 `MPPI + ICODE` 闭环导航与避障。
- 使用 ICODE 替代 MPPI rollout 的动力学预测部分（环境真实动力学保持 MuJoCo）。
- 形成可复现的数据采集、转换、训练、评测与可视化链路。

## 2. 系统总体架构
- 控制器：`MPPI`
- 预测模型：`ICODE`（可与差速运动学做 hybrid）
- 环境：`E1_SimpleSensor.xml`（MuJoCo 真值 + 传感器）
- 训练数据：四层结构（raw / derived / state_est / gt）

关键入口：
- 可视化运行：`run_icode_mppi_e1_viewer.py`
- 批量测试：`run_icode_mppi_e1_test.py`
- 训练评测：`train_icode_and_eval.py`
- 环境包装：`env_mujoco.py`

## 3. 改进路线（按阶段）

### 阶段 A：链路打通
- 完成 MPPI 与 ICODE 的接口联通（先随机权重/占位模型验证）。
- 建立 E1 场景下的基础控制与可视化。

### 阶段 B：数据闭环
- 建立 MuJoCo 多层数据采集与转换脚本。
- 形成训练 bundle，支持切分与统计（mean/std）。

### 阶段 C：控制行为修复
- 引入 `global guide + path reference`，降低纯局部策略的抖动。
- 引入 `auto waypoint + corridor commit`，减少在障碍附近反复横跳。
- 加入 `goal direct on clear`，在视线清晰时直接终点引导。
- 加入 `dock` 终点停车状态机，改善“冲过头/停不稳”。

### 阶段 D：稳定性增强
- 用 `STOP -> ROTATE -> FORWARD` 恢复状态机替代简单倒车逃逸。
- 引入 `progress hard gate`（路径剩余长度窗口）检测“无进展”。
- 引入 `boundary hard guard` 防止越界跑飞。
- 增加 anti-cheat 约束（抑制“朝向 goal 却长期反向输出”）。

### 阶段 E：场景复杂度提升
- E1 场景支持 5 障碍（front/left/right/mid_left/mid_right）。
- 支持障碍随机化 + 可通过性约束采样（避免无解场景）。

### 阶段 F：自适应调度（实验分支）
- 在分支 `exp_adaptive_try` 增加可开关调度器：
  - 模式：`OPEN / TIGHT / STUCK / DOCK`
  - 按 `clearance/progress/oscillation/dist_to_goal` 在线切换
  - 在线 EMA 调整 MPPI 权重与噪声
- 默认关闭，不影响基线可复现性。

## 4. 当前分支与版本冻结
- 基线分支：`baseline_before_adaptive_20260313`
- 自适应实验分支：`exp_adaptive_try`
- 已在仓库保存 E1 XML 快照：`snapshots/E1_SimpleSensor_20260313.xml`

## 5. 当前风险与后续方向
- 窄缝场景仍可能出现“犹豫/转圈”，主要受代价对称性与模型误差影响。
- 已具备两条可并行优化线：
  1. 更强专家数据 + 再训练 ICODE
  2. 保守/激进调度参数网格化评估（按场景统计成功率、耗时、碰撞率）

## 6. 对外汇报建议指标
- 场景成功率（到达 goal）
- 平均到达步数/时间
- 碰撞步数占比
- 最小安全间隙
- 轨迹平滑度（控制增量均值）
- 自适应模式切换次数（开启调度时）
