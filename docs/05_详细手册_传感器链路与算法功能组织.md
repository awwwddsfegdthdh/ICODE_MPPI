## 1. 系统总览（从采集到闭环）

链路分为 5 段：
1. MuJoCo 仿真产生传感器与真值。
2. 采集脚本按四层结构存盘（raw/derived/state_est/gt，其中 collect 阶段写 raw+gt+meta）。
3. 转换脚本把 raw+gt 变成 ICODE 与 MPPI 直接可用输入。
4. 训练脚本训练 ICODE（并做 groundtruth 评测）。
5. 运行脚本在 MuJoCo 中做闭环控制与可视化。

关键文件：
- `collect_mujoco_multilayer_data.py`
- `convert_multilayer_dataset.py`
- `prepare_icode_training_data.py`
- `train_icode_and_eval.py`
- `env_mujoco.py`
- `mppi.py`
- `mppi_nav_utils.py`
- `run_icode_mppi_e1_viewer.py`
- `run_icode_mppi_e1_test.py`

## 2. 传感器信息与处理链路

### 2.1 传感器来源（MuJoCo）
主要读以下信号：
- 轮速与轮位：`wheel_l_pos`, `wheel_r_pos`, `wheel_l_vel`, `wheel_r_vel`
- IMU：`imu_acc`, `imu_gyro`
- 触碰：`touch_front_force`
- 低维测距：`lidar_left30`, `lidar_front`, `lidar_right30`
- 真值姿态：`base_pos_gt`, `base_quat_gt`, `base_linvel_gt`, `base_angvel_gt`
- 相机真值：`camera_pos_gt`, `camera_quat_gt`
- 目标真值：`goal_pos_gt`
- 障碍真值：`obs_*_pos_gt`（按 XML 实际存在的障碍自动发现）
- 深度图：`raw__depth_image / raw__distance_image / raw__depth_valid_mask`（由 renderer 渲染，不在 `sensordata` 标量流里）

### 2.2 四层数据结构

#### Layer A: 原始传感器流（raw）
由采集脚本直接落盘，典型键：
- `raw__episode`, `raw__step`, `raw__sim_time`
- `raw__ctrl_applied`（2 维左右轮控制）
- `raw__wheel_pos`, `raw__wheel_vel`
- `raw__imu_acc`, `raw__imu_gyro`
- `raw__touch_front_force`
- `raw__lidar_triplet`（左/前/右）
- 可选 `raw__depth_image`, `raw__distance_image`, `raw__depth_valid_mask`

#### Layer B: 派生感知特征（derived）
由转换脚本计算：
- `derived__goal_rel_body`：目标在车体坐标下位置
- `derived__goal_dist`：目标距离
- `derived__goal_heading_err`：目标航向误差
- `derived__depth_sector_min`：左右前三扇区最小可行深度（这里由 lidar_triplet 清洗后形成）
- `derived__free_corridor_width`：可通行走廊宽度估计
- `derived__depth_collision_flag`：近距碰撞风险标记
- `derived__touch_flag`：触碰标记

#### Layer C: 状态估计（state_est）
固定 7 维：
- `state_est__x_t = [x_odom, y_odom, psi_odom, v_body, wz_body, dqL, dqR]`

估计方式：
- `v_body = r * (dqR + dqL)/2`
- `wz_wheel = r * (dqR - dqL)/wheel_base`
- `wz_body = alpha * wz_wheel + (1-alpha) * imu_wz`
- `x/y/psi` 可选：
  - `pose_source=odom`：积分得到
  - `pose_source=gt`：直接用真值位姿（用于评测与稳定控制）

#### Layer D: 监督真值（gt）
用于训练对照、误差评估、可视化排查：
- `gt__base_*`, `gt__camera_*`, `gt__goal_pos_gt`, `gt__obs_pos_gt`
- 兼容键：`gt__target_pos_gt`

### 2.3 ICODE/MPPI 输入映射
转换后给下游的核心键：
- ICODE：
  - `icode__x_t`（7D）
  - `icode__u_t`（2D）
- MPPI：
  - `mppi__state_t`（7D）
  - `mppi__u_t`（2D）
  - `mppi__u_prev`（上一时刻控制）
  - `mppi__cost_context`（代价函数上下文特征）

### 2.4 维度与单位速查
- `raw__ctrl_applied`: `[N, 2]`，左右轮控制（与 actuator 范围同单位）
- `raw__wheel_vel`: `[N, 2]`，单位 rad/s
- `raw__imu_gyro`: `[N, 3]`，单位 rad/s
- `raw__lidar_triplet`: `[N, 3]`，单位 m（左/前/右）
- `state_est__x_t`: `[N, 7]`，`[m,m,rad,m/s,rad/s,rad/s,rad/s]`
- `icode__u_t`: `[N, 2]`，与控制输入同尺度
- `mppi__cost_context`: `[N, C]`，`C` 由当前特征拼接定义决定（固定宽度）

### 2.5 时间对齐规则（为什么可用于下一步预测）
- 控制是离散时间序列 `u_t`，状态是 `x_t`。
- 训练样本按 transition 构造：`(x_t, u_t) -> x_{t+1}`。
- `prepare_icode_training_data.py` 默认要求同 episode 且 step 连续，避免跨轨迹拼接污染。
- 若存在 `raw__sim_time`，会同时写入 `dt`，可用于非等间隔数据的诊断。

## 3. 场景生成与可通过性约束

采集与测试支持每个 episode 随机场景，核心机制：
- 随机 robot 初始位姿
- 随机 goal
- 随机 3~5 个障碍位置与半径（可约束范围）
- rejection sampling 约束：
  - 障碍-障碍最小间距
  - 障碍-起点最小间距
  - 障碍-goal 最小间距
- 可选“全局路径可达”约束（栅格 BFS）
- 可选“主连线阻挡 + 两侧分布”约束，让场景具有避障意义
- 失败回退默认布局，避免采集中断

scene 采样结果会写入 `meta__episode_*`，保证可复盘。

## 4. 运行时算法组织（闭环控制）

### 4.1 运行主循环（viewer/test 通用）
每个控制周期：
1. 从环境拿当前 7D 状态、障碍、goal、触碰、最小间隙。
2. 目标管理：全局引导点 / 自动 waypoint / 直达 goal 三者择优。
3. 恢复与安全层：碰撞恢复、边界约束、进展门控。
4. MPPI 采样 N 条控制序列，在 horizon 内 rollout。
5. 用 cost 聚合并 softmin 加权，得到当前 action。
6. 经过动作平滑与限幅后施加到 MuJoCo。
7. 记录指标，判断终止条件。

模块拼装顺序（代码结构）：
1. `env_mujoco.py` 提供状态估计与场景接口。
2. `run_icode_mppi_e1_viewer.py`/`run_icode_mppi_e1_test.py` 负责目标管理与状态机调度。
3. `mppi_nav_utils.py` 提供 LOS、全局路径、waypoint、场景采样等几何工具。
4. `mppi.py` 执行 MPPI rollout + 代价评估 + softmin 更新。
5. `icode_dynamics.py`（或 hybrid）提供 rollout 动力学预测。

### 4.2 预测模型层
- `planner-model=kinematic`：纯差速运动学
- `planner-model=icode`：纯 ICODE 网络动力学
- `planner-model=hybrid`：ICODE 与运动学加权融合（`icode_blend_alpha`）

### 4.3 MPPI 代价函数组成（当前版本）
主要项包括：
- 目标距离与终端距离
- 目标方向对齐与前进约束
- 反向运动惩罚
- 远离目标惩罚（逐步）
- 近障碍/碰撞惩罚
- 控制能量与控制平滑惩罚
- 近终点停车惩罚（防冲过头）
- 参考路径跟踪项（track/progress/backtrack/terminal）
- 边界惩罚
- goal 视线可见性奖励

结论：当前不是单一“终端距离最小化”，而是多目标结构化代价。

### 4.4 路径与决策增强模块
当前可用模块：
- `global_guide`：基于栅格全局路径取 lookahead 目标
- `auto_waypoint`：主目标被阻挡时自动选侧向中间航点
- `corridor_commit`：进入可行侧向通道后短时锁定，防左右来回抖动
- `goal_direct_on_clear`：当 goal 视线连续清晰，切换为直达
- `dock` 终点停车状态机：接近 goal 后转为制动+姿态收敛
- `recover` 恢复状态机：`STOP -> ROTATE -> FORWARD`
- `boundary_guard`：防跑飞
- `anti_cheat` 反掩耳盗铃约束：抑制“朝向目标但持续倒车”

### 4.5 自适应调度器（分支能力）
可开关 `--adaptive-scheduler`，模式：
- `OPEN`：开阔区域
- `TIGHT`：窄通道
- `STUCK`：低进展/高振荡
- `DOCK`：终点靠近段

调度器根据 clearance/progress/oscillation/dist_to_goal 切换模式，并对 MPPI 权重与噪声做 EMA 调整。

### 4.6 终点停车状态机（当前实现意图）
- `NAV`：正常导航阶段，以路径/目标推进为主。
- `DOCK`：进入终点邻域后，降低线速度并控制姿态误差，抑制冲过头和来回摆。
- 退出条件由 `dock_enter_radius / dock_exit_radius` 控制，避免频繁抖动切换。

## 5. 训练链路组织

### 5.1 转换与打包
1. `convert_multilayer_dataset.py`：原始采集集 -> 转换集（包含 derived/state_est/icode/mppi 键）
2. `prepare_icode_training_data.py`：多文件合并、transition 构建、train/val/test 划分、mean/std 统计

### 5.2 训练与评估
`train_icode_and_eval.py` 主要功能：
- 自动设备选择（支持 CUDA）
- AMP（fp16/bf16）
- torch.compile
- Adam/AdamW + fused optimizer
- onecycle/cosine/no scheduler
- one-step loss + multi-step rollout loss（late bias + terminal weight）
- EMA 权重维护与 EMA 评估
- resume（默认支持从 best 继续，含 optimizer/scheduler）
- 保存 `icode_best.pt`、`icode_last.pt`、`metrics.json`、`history.npz`

## 6. 终止条件与“为什么结束”

常见结束判据：
- 到达判据：`dist_to_goal < goal_tol`（若 `stop_on_goal` 还要求速度足够小）
- 超步数：`step >= max_steps`
- 安全/恢复触发导致提前收敛或停止

建议对外汇报时同时报告：
- `reached_goal`
- `final_dist_to_goal`
- `min_dist_to_goal`
- `collision_steps`
- `goal_blocked_ratio`
- `adaptive_mode_steps`（开启调度时）
